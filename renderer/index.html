Any HTTP(S) endpoint works, including Azure/AWS storage, OpenAI APIs and container services. HTTP(S) uses a curl-style GET; IP checks use ping (PsPing-style reachability), and TCP ports use a telnet-style connect without sending data. No external tools are required.

Quick add:
IP checks use ping (with TCP fallback, similar to PsPing); ports use a TCP connect (telnet-style, no data sent) to the IP address or URL host. Custom ports: type the number, optionally with a name - 9000:minio.

Global DNS

Used for HTTP checks, automatic IP resolution and as the default server in DNS lookups. Up to 4 IPv4/IPv6 addresses (optional :port). Leave empty to use the system resolver. Names these servers can't resolve fall back to the system resolver (hosts file, intranet).

Data

Hosts import from JSON, CSV (columns: name, url, ip, ports, pingPort, intervalMinutes, enabled) or a plain text list with one URL/IP per line. Duplicates are skipped.

Application data, settings, history, credentials and logs are stored in the portable appdata folder (logs/devoping.log).

Usage data

On by default - you can turn it off at any time. Devoping sends anonymous aggregate counts (number of hosts, checks passed/failed, features used, app/OS version) to help improve the product. Never hostnames, URLs, IP addresses, usernames or error text.
